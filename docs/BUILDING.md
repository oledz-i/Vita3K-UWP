# Build the UWP development shell

## GitHub Actions

The `UWP development package` workflow uses GitHub's hosted `windows-2022` runner, Visual Studio 2022 and SDK 10.0.22621.0. Push to `main`, open a pull request, or select **Actions → UWP development package → Run workflow**. No personal computer, self-hosted runner registration, certificate upload or repository secret is needed.

The workflow validates repository files, compiles a native x64 UWP application, packages APPX, signs it with a disposable development certificate, verifies its signature, and uploads the package and diagnostics separately. It fails if compilation, packaging, signing or artifact discovery fails. Dependencies generated by MSBuild stay beside the package. The Actions badge indicates CI results, not successful Xbox execution.

The package version is `0.1.<run number>.0` (run numbers must fit 0–65535). Manual local builds default to `0.1.0.0`. Pull-request runs have read-only repository permissions and use no production signing credentials. Only the public `.cer` is exported; the private key is removed from the runner's user certificate store at the end.

## Local Windows build

Install Visual Studio 2022 with **Universal Windows Platform development**, C++ UWP build tools for x64 (v143), and **Windows SDK 10.0.22621.0**. Install Git, Python 3 and PowerShell 7. Then, from an elevated PowerShell session at the repository root:

```powershell
python scripts/validate.py
./scripts/build-appx.ps1 -BuildNumber 1
```

Output: `artifacts/package/`. Logs: `artifacts/logs/build.binlog`. Move previous package artifacts before another build; the script rejects a nonempty package directory to prevent stale packages from being uploaded. The original manifest is restored after building. The local script temporarily adds its development certificate to the Local Machine TrustedPeople store for signature verification and removes it afterward.

The project can also be opened directly at `src/Vita3K.UWP/Vita3K.UWP.vcxproj`. Only Release/x64 is configured. This small shell uses C++/CX for UWP activation and XAML status text. That is a bootstrap choice; it does not dictate the eventual emulator UI or the core's C++23 build configuration.

## Upstream source

```powershell
./scripts/fetch-upstream.ps1
```

This creates an ignored `upstream/` checkout at the revision in `upstream.lock.json`, including submodules. It refuses to overwrite an existing directory. It is a research/integration checkout, not part of the shell build. Change the lock only after reviewing and recording a new upstream revision.

Do not package upstream's desktop executable as a substitute for a UWP port. The core, dependencies, frontend, memory APIs and GPU backend need actual adaptation.

## Troubleshooting

- **Missing SDK/toolset:** install the exact SDK and C++ UWP components; inspect the MSBuild log.
- **APPX not found:** inspect packaging errors; do not suppress the check or upload an empty artifact.
- **Signing/trust failure:** ensure the publisher exactly matches the certificate subject. The test certificate is not a release identity.
- **Workflow waiting:** check the repository Actions page for runner availability or account-level Actions restrictions.
- **Package succeeds but Xbox fails:** report console OS, package version, error code and logs. Hosted Windows compilation cannot prove Xbox compatibility.
